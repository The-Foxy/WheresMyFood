# غذام کو؟ — دستیار لوکال اسنپ‌فود

نسخهٔ فعلی: **۱٫۰٫۰** — انتشار رسمی با نصاب دابل‌کلیکی چندمرورگره و آپدیت خودکار گیت‌هاب.

افزونهٔ مستقل Manifest V3 برای Chrome، Edge، Brave و Chromium.

## نصب سریع با آپدیت خودکار (پیشنهادی)

۱. یک بار فایل **[wheresmyfood-setup.zip](https://github.com/The-Foxy/WheresMyFood/releases/latest)** را از Releases پروژه بگیر و Extract کن.
۲. روی ویندوز فایل **`Install-Windows.bat`** و روی مک **`Install-macOS.command`** را دابل‌کلیک کن (روی لینوکس `./install-linux.sh` یا `python3 updater/install.py` را اجرا کن). نصاب به‌صورت خودکار اتصال آپدیتر را برای همهٔ مرورگرهای کرومیوم ثبت می‌کند، مسیر پوشهٔ افزونه را در کلیپ‌بورد کپی می‌کند و صفحهٔ راهنمای تکمیل نصب (`setup-guide.html`) را باز می‌کند.
۳. در مرورگر وارد `chrome://extensions` یا `edge://extensions` شو، گزینهٔ **Developer mode** را روشن کن و با **Load unpacked** (و زدن `Ctrl+V`) یا کشیدن و رها کردن پوشهٔ `extension`، افزونه را یک بار معرفی کن.

این نصب شناسهٔ ثابت خودش را دارد و تنظیماتت در تمام آپدیت‌های بعدی حفظ می‌شوند (اجرای مجدد نصاب هم در صورت نیاز اتصال را بدون پاک‌کردن یا دانگرید افزونه تعمیر می‌کند).

مرورگر موقع اجرا و هر ۶ ساعت Release پایدار همین ریپو را بررسی می‌کند. بسته اول جداگانه دریافت می‌شود؛ اندازه و SHA-256 با API گیت‌هاب تطبیق داده می‌شوند. وقتی همهٔ تب‌های ابزار آزاد بودند، نسخه جایگزین و افزونه خودکار Reload می‌شود؛ برنامهٔ دائمی یا Git لازم نیست. یک نسخهٔ قبلی نگه داشته می‌شود و خطای جایگزینی نسخهٔ قبلی را برمی‌گرداند. اطلاعات نامطمئن، فایل اجرایی یا بسته‌ای که به دامنه‌های خارج از اسنپ‌فود دسترسی بخواهد خودکار نصب نمی‌شود.

وضعیت و دکمهٔ بررسی دستی داخل بخش «به‌روزرسانی ابزار» در پنل هست. [راهنمای کامل نصب و انتشار](updater/README.md). بستهٔ تکی `snappfood-assistant.zip` هم همچنان برای نصب دستی/توسعه وجود دارد.

معیارها: محدودهٔ **قیمت خود غذا بعد از تخفیفِ قابل مشاهده**، حداکثر زمان تخمینی تحویل و حداقل امتیاز رستوران. ارسال، مالیات و بسته‌بندی وارد فیلتر نمی‌شن. امتیاز غذا، اگر منبع بده، جدا نمایش داده می‌شه.

## پیش‌نمایش

از این فولدر `npm run preview` رو اجرا کن و برو به:

http://127.0.0.1:18770/demo/

**این صفحه دادهٔ نمونه داره، نه منوی زندهٔ موقعیت کاربر.** فرم، فیلتر، پیشرفت، توقف و مرتب‌سازی از همون کد افزونه استفاده می‌کنن. شکل غذاها تصویرسازی نمایشی‌ان.

## نصب واقعی

۱. Chrome: `chrome://extensions` یا Edge: `edge://extensions`.
۲. Developer mode → Load unpacked → همین فولدرِ دارای manifest.json.
۳. داخل همون مرورگر وارد https://snappfood.ir شو و خودت آدرس رو انتخاب کن؛ صفحه رو Reload کن.
۴. دکمهٔ «غذام کو؟» پایین سمت چپ صفحه، یا آیکن افزونه، پنل رو باز می‌کنه.
۵. محدوده‌ها رو تعیین کن و «غذامو پیدا کن» رو بزن.

نصب unpacked در مرورگر داخلی Codex پشتیبانی نمی‌شه. رابط این نسخه لوکالی بررسی می‌شه؛ **جستجوی زنده با حساب کاربر هنوز نیاز به تست در Chrome/Edge بعد از نصب داره**. تغییر مسیر یا ساختار API غیررسمی ممکنه نیاز به اصلاح adapter داشته باشه. خطای 403 دور زده نمی‌شه؛ ورود/دسترسی صفحه باید توسط کاربر بررسی بشه.

## روش جستجو

- موقعیت از درخواست‌ها/لینک‌های همین تب اسنپ‌فود خونده می‌شه؛ مختصات توی حافظه می‌مونه.
- فقط GET فهرست عمومی رستوران‌ها روی snappfood.ir و منوی فعلی روی apigw.snappfood.ir/menu-read-model/{code} مجازه. درخواست منو از داخل صفحهٔ اسنپ‌فود و با CORS عادی مرورگر فرستاده می‌شه. کوکی‌ها رو خود مرورگر مثل درخواست عادیِ سایت پیوست می‌کنه؛ افزونه رمز، کوکی، توکن یا localStorage سایت رو نمی‌خونه.
- فهرست صفحه‌به‌صفحه تا پایان صریح/صفحهٔ واقعاً خالی پیمایش می‌شه؛ صفحهٔ تکراری یا سقف محافظتی ۱۰۰ صفحه، نتیجهٔ «ناقص» می‌ده.
- رستوران‌های بسته، دیرتر از سقف زمان یا پایین‌تر از امتیاز انتخابی کنار گذاشته می‌شن. زمان نامشخص با زمان صفر جایگزین نمی‌شه.
- منوهای باقی‌مونده یکی‌یکی با فاصلهٔ حداقل ۴۵۰ میلی‌ثانیه دریافت می‌شن. سایزهای مستقل، غذای ناموجود و دسته‌های تکراری مدیریت می‌شن.
- قیمت و امتیاز مجهول حدس زده نمی‌شن. امتیاز ۰–۱۰ API به ۰–۵ نمایش سایت تبدیل می‌شه.
- خطای 429 مکث می‌ده و Retry-After رعایت می‌شه. خطای ورود/مسدودی کل جستجو رو مکث می‌ده. منوهای ناموفق قابل تلاش دوباره‌ان.
- سه خطای 400 متوالیِ منو هم جستجو رو مکث می‌ده؛ همهٔ رستوران‌ها با یک درخواست ناسازگار دوباره امتحان نمی‌شن. پاسخ خطا فقط کد سرویس و نام فیلدهای نامعتبر رو نشون می‌ده، نه متن خام یا اطلاعات حساب.
- توقف درخواست تازه‌ای نمی‌فرسته؛ درخواستِ در حال انجام ممکنه حداکثر ۲۲ ثانیه طول بکشه. نتایج و checkpoint فقط تا Reload همین صفحه داخل حافظه باقی می‌مونن.
- قبل از هر منو و هر صفحه، عوض‌شدن موقعیت بررسی می‌شه. نتایج آدرس قدیمی در این حالت پاک می‌شن.
- کد فقط روی snappfood.ir دسترسی داره؛ سفارش، سبد، پرداخت و ارسال داده به سرویس بیرونی پیاده‌سازی نشده.

## توسعه و بسته‌بندی

بدون کتابخانه و بدون مرحلهٔ build:

```bash
npm test
npm run package
```

ساختار: `src/core.js` برای نرمال‌سازی و فیلتر، `src/engine.js` برای پیمایش و checkpoint، `src/background.js` برای درخواست‌های محدود به تب، `src/app.js` برای رابط مشترک پیش‌نمایش و افزونه.

مسیرهای اولیهٔ adapter از بررسی تب واقعی اسنپ‌فود و مطالعهٔ پیاده‌سازی مستقل [snapp-mcp](https://github.com/sepehr071/snapp-mcp) به‌دست اومدن. کد این افزونه مستقل نوشته شده و هیچ بسته‌ای از اون پروژه نصب یا اجرا نشده.

## به‌روزرسانی ۰٫۱٫۱

در بررسی تازهٔ درخواست‌های صفحهٔ واقعی در ۱۷ نوامبر ۲۰۲۶، endpoint فعلی منو `https://apigw.snappfood.ir/menu-read-model/{code}` بود؛ نسخهٔ ۰٫۱٫۰ از endpoint قدیمی dynamic استفاده می‌کرد که در تست کاربر برای منوها HTTP 400 داد. مسیر منو و پشتیبانی از قالب دسته/محصول/سایز و discount.amount اصلاح شد. این اصلاح هنوز نیاز به تأیید اجرای زندهٔ Chrome کاربر داره؛ پیش‌نمایش به‌تنهایی تأیید اتصال زنده نیست.

بعد از تغییر کد: در chrome://extensions گزینهٔ **Reload خود افزونه** رو بزن، سپس تب اسنپ‌فود رو هم Reload کن. بالای پنل باید شمارهٔ آخرین نسخه دیده بشه. تنظیمات فیلتر محفوظ می‌مونن؛ checkpoint درون حافظه با Reload صفحه پاک می‌شه.

## به‌روزرسانی ۰٫۱٫۲ — لینک خود غذا

کاربر تأیید کرد دریافت غذاها در ۰٫۱٫۱ کار می‌کنه. دکمهٔ نتیجه قبلاً فقط صفحهٔ رستوران رو باز می‌کرد. حالا شناسهٔ اصلی غذا جدا از شناسهٔ سایز حفظ می‌شه و لینک بومی اسنپ‌فود ساخته می‌شه:

`/restaurant/menu/{vendor}/product/{title}-pp:{parentId}/?product_id={variationId}`

این مسیر با غذای واقعی «آش رشته»، parent ID برابر 180 و variation ID برابر 7075157، داخل مرورگر بررسی شد؛ صفحهٔ جزئیات خود غذا باز شد. اسنپ‌فود توی اون صفحه ممکنه همهٔ سایزهای همون غذا رو نشون بده؛ افزونه چیزی به سبد اضافه نمی‌کنه.

اگر پاسخ منبع شناسهٔ اصلی رو نده، شناسهٔ سایز جای اون حدس زده نمی‌شه؛ لینک «همین غذا در منو» با `#sf-food={variationId}` باز می‌شه. افزونه بعد از آماده‌شدن DOM، ردیف دقیق سایز رو اسکرول و ۱۲ ثانیه مشخص می‌کنه. این حالت به نصب افزونه وابسته‌ست؛ لینک بومی غذا مستقل از افزونه هم کار می‌کنه.

برای دریافت لینک‌های جدید، افزونه و تب رو Reload کن؛ **v0.1.2** باید بالای پنل باشه و بعد یک جستجوی تازه انجام بده.

## به‌روزرسانی ۰٫۱٫۳ — غذام کو؟، هزینهٔ پیک و شمارش روشن‌تر

اسم ابزار توی پنل، دکمهٔ شناور و فهرست افزونه‌ها «غذام کو؟» شد. روی هر کارت، هزینهٔ پیک جدا از قیمت غذا نمایش داده می‌شه؛ مقدار صفر «رایگان» و مقدار دریافت‌نشده «نامشخص»ه. تخفیف پیک فقط وقتی اعمال می‌شه که پاسخ اسنپ‌فود فعال‌بودنش رو مشخص کرده باشه. این مبلغ از فهرست همون رستوران برای آدرس انتخابی میاد و درخواست تازه‌ای لازم نداره؛ مبلغ نهایی سفارش ممکنه موقع پرداخت تغییر کنه.

عدد «رستوران مناسب زمان و امتیاز» تعداد غذا نیست. مثلاً ۱۰۵ رستوران می‌تونن بعد از بررسی منوها فقط ۳ گزینهٔ غذا/سایز مطابق قیمت، عبارت جستجو و حذف مخلفات داشته باشن. هر سایز جدا حساب می‌شه. بخش جمع‌شوندهٔ «این عددها چطور حساب شدن؟» تعداد منوها، گزینه‌های ناموجود، قیمت نامشخص و حذف با فیلترها رو نشون می‌ده. عبارت اختیاری و حذف مخلفات هم کنار محدودهٔ نتایج نوشته می‌شن.

این شمارش مربوط به منوهای قابل دریافت توی همون اجراست؛ تضمین تعداد کل غذاهای اسنپ‌فود در همهٔ زمان‌ها نیست. برای دیدن تغییرات، خود افزونه رو در chrome://extensions و بعد تب اسنپ‌فود رو Reload کن، **v0.1.3** رو بالای پنل ببین و یک جستجوی تازه بزن.

## به‌روزرسانی ۰٫۱٫۴ — آیکن و دکمهٔ شناور

آیکن چنگال و علامت سؤال ضخیم‌تر شد؛ برای نوار ابزار مرورگر هم PNG در چهار اندازه اضافه شد. دکمهٔ شناور در حالت عادی فقط آیکنه؛ با موس یا فوکوس کیبورد باز می‌شه و اسم ابزار رو نشون می‌ده. تنظیم کاهش حرکت سیستم هم رعایت می‌شه. افزونه و تب اسنپ‌فود رو Reload کن؛ نسخهٔ پنل باید v0.1.4 باشه.

## به‌روزرسانی ۰٫۱٫۵ — اصلاح آیکن و چیدمان دکمه

اسم پررنگ‌تر در سمت چپ آیکن باز می‌شه؛ عرض دکمه اندازهٔ محتوای خودشه و گوشه‌ها گردتر شدن. مشکل تبدیل SVG به PNG که خطوط آیکن افزونه رو حذف می‌کرد هم با رندر صحیح اصلاح شد. خود افزونه و تب رو Reload کن؛ نسخه باید v0.1.5 باشه.

## به‌روزرسانی ۰٫۱٫۶ — منوهای تدریجی

لینک «همین غذا در منو» علاوه بر انتظار برای DOM، تا ۴۵ ثانیه منو رو تدریجی اسکرول می‌کنه تا بخش‌های پایین‌تر بارگذاری بشن. بعد از پیدا شدن شناسهٔ دقیق غذا، اون رو وسط صفحه میاره و مشخص می‌کنه. اسکرول، لمس یا کلیک دستی، کلیدهای حرکت، رفتن به صفحهٔ دیگه و مخفی‌شدن تب این جستجو رو متوقف می‌کنن. این تغییر مخصوص لینک‌های جایگزین منوئه؛ لینک بومی صفحهٔ جزئیات غذا تغییر نکرده.

پشتیبانی اختصاصی از تخفیف پرو هنوز تأیید نشده؛ نیاز به مقایسهٔ قیمت و قالب پاسخ منوی حساب پرو داره. تخفیف دلخواه یا درصدی از روی نام اشتراک اعمال نمی‌شه.

## به‌روزرسانی ۰٫۱٫۷ — حساب و تخفیف پرو (در ۰٫۱٫۸ کنار گذاشته شد)

بالای پنل وضعیت پرو و دکمهٔ «بررسی حساب» اضافه شد. قبل از هر جستجو هم وضعیت دوباره بررسی می‌شه: یک تب موقتِ غیرفعال از صفحهٔ اصلی اسنپ‌فود باز می‌شه، فقط متن صریح عضویت/ورود از DOM خونده می‌شه و تب بسته می‌شه. نتیجه در حافظهٔ افزونه می‌مونه، نه روی دیسک. این کار رمز، توکن، کوکی یا محتوای سفارش‌ها رو نمی‌خونه. اگر عضویت قابل تأیید نباشه، وضعیت «تأیید نشد» نمایش داده می‌شه؛ تبلیغ پرو روی رستوران اثبات عضویت حساب نیست.

تخفیف عادی و تخفیف پرو پشت سر هم حساب می‌شن، نه با جمع درصدها. فیلدهای صریح قیمت پروی غذا پشتیبانی شدن. endpoint محدود vendor-rewards/{code} هم برای شرایط کوپن پرو اضافه شد؛ درخواست‌ها مثل منو از تب اسنپ‌فود و با نشست عادی مرورگر فرستاده می‌شن. فقط کوپنِ قابل تأیید برای سفارش همین یک غذا، با حداقل مبلغ و سقف تخفیف معلوم، می‌تونه قیمت و فیلتر رو تغییر بده. کوپن شرطی، بازگشت وجه و شرط نامعلوم فقط توضیح داده می‌شن؛ چند کوپن با هم جمع نمی‌شن. هزینهٔ پیک هنوز جداست و تخفیف ارسالِ کوپن به قیمت غذا منتقل نمی‌شه.

اگر یک سایز توی چند بخش منو قیمت متفاوت داشته باشه، پایین‌ترین پیشنهاد موجود نگه داشته می‌شه؛ شمارش و لینک اصلی غذا حفظ می‌شن. افزونه و تب رو Reload کن و جستجوی تازه بزن؛ نسخه باید v0.1.7 باشه.

## به‌روزرسانی ۰٫۱٫۸ — قیمت خود منو، بدون بررسی حساب

دکمه، منطق و تب تشخیص حساب و محاسبهٔ تخفیف پرو از فیلدهای حدسی حذف شدن. به‌جاش برای هر رستوران مناسب، یک تب منوی غیرفعال در همین مرورگر باز می‌شه؛ صفحه با نشست عادی خود اسنپ‌فود بارگذاری می‌شه و قیمت نهایی از کارت واقعی غذا خوانده می‌شه (`data-variation-id` و `data-discounted-price`). تخفیف پرو دوباره از این قیمت کم نمی‌شه. قیمتِ همین صفحه مبنای فیلتر و مرتب‌سازی و نمایش نتیجه‌ست. این عدد قیمت منوئه، نه تضمین مبلغ نهایی سبد خرید.

این روش از درخواست API تنها کندتره؛ هم‌زمان فقط یک تب موقت بازه، بعد از خواندن منو یا توقف بسته می‌شه. پنل اسم منوی در حال بررسی رو نشون می‌ده. قیمت خوانده‌نشده حدس زده نمی‌شه؛ گزینهٔ نامعلوم کنار گذاشته می‌شه و منو برای تلاش دوباره ناقص می‌مونه. سقف خواندن هر منو ۴۵ ثانیه‌ست. هیچ دکمهٔ سفارش یا سبدی کلیک نمی‌شه؛ کوکی، توکن و اطلاعات حساب هم خوانده یا ذخیره نمی‌شن.

لینک اصلی نتیجه حالا منو رو با شناسهٔ دقیق غذا باز می‌کنه. اسکرول به ظرف واقعی `main-container` وصل شد؛ هدف‌های دیرلودشده و لینک‌های بازشده در تب پس‌زمینه هم مدیریت می‌شن. با دخالت دستی کاربر، اسکرول خودکار متوقف می‌شه. افزونه و تب اسنپ‌فود رو Reload کن؛ v0.1.8 رو ببین و یک جستجوی تازه انجام بده.

## به‌روزرسانی ۰٫۱٫۹ — برگشت جستجوی سریع

جستجوی پیش‌فرض دوباره فقط از API منو استفاده می‌کنه؛ هیچ تب منویی باز نمی‌شه. خواندن تمام صفحهٔ هر رستوران در نسخهٔ قبل عامل کندی بود. «بررسی دقیق‌تر قیمت» به شکل یک بخش جمع‌شونده اضافه شد؛ تطبیق صفحه‌ای فقط با تیک صریح کاربر اجرا می‌شه و هزینهٔ بازشدن تب موقت هم همون‌جا توضیح داده شده. با Reload پنل، این گزینه همیشه خاموشه، حتی اگر قبلاً در تنظیمات ذخیره شده باشه. عوض‌کردن این حالت هم checkpoint رو جدا می‌کنه.

حالت سریع قیمت تخفیف‌خوردهٔ پاسخ منو رو می‌گیره؛ کوپن‌های شرطی سفارش ممکنه در اون پاسخ نباشن. برای قیمت دقیق صفحه می‌تونی حالت کندتر رو انتخاب کنی. اصلاح اسکرول مستقل از این انتخاب باقی مونده. اگر جستجوی قدیمی هنوز در جریانه اول توقفش بده؛ افزونه و تب رو Reload کن و v0.1.9 رو ببین.

## به‌روزرسانی ۰٫۲٫۰ — انتخاب بخش و نوع غذا

دو انتخاب جمع‌وجور به بالای فرم اضافه شد: «بخش اسنپ‌فود» و، فقط داخل رستوران، «نوع غذا». بخش‌ها شامل رستوران، کافه، شیرینی، نانوایی، آبمیوه و بستنی، میوه، پروتئین و تره‌بار هستن؛ سوپرمارکت/اسنپ‌اکسپرس کلاً وارد این ابزار نشده.

نوع غذا مطابق دسته‌های خود سایت شامل فست‌فود، ایرانی، کباب، رژیمی، گیاهی، آش و حلیم، طباخی، صبحانه و میان‌وعده، سالاد، دریایی و بین‌الملله. این انتخاب فهرست **فروشگاه‌های آن دسته** رو از سرور محدود می‌کنه؛ قرار نیست از روی اسم رستوران حدس بزنه یا تضمین کنه تمام غذاهای یک فروشگاه چندمنظوره فقط از همون نوع هستن. برای محدودکردن اسم غذا، کادر عبارت اختیاری هم همچنان قابل استفاده‌ست.

مسیرهای دسته‌بندی و شناسه‌ها از رابط، لینک‌ها و URL درخواست‌های عمومی خود سایت در ۲۲ نوامبر ۲۰۲۶ بررسی شدن. برای انتخاب‌های جدید از مسیر بومی `/search/api/v4/restaurant/vendors-list` با `sp_alias` و دستهٔ صریح `{value,sub}` استفاده می‌شه؛ درخواست پیش‌فرضِ قبلیِ رستوران بدون زیرگروه محفوظ مونده. لینک منو و اسکرول هم با بخش فروشگاه هماهنگ شدن. انتخاب بخش و نوع غذا داخل تنظیمات فیلتر ذخیره می‌شه و تغییرش checkpoint قبلی رو برای بخش جدید استفاده نمی‌کنه.

فیلتر مخلفات و نوشیدنی فقط برای رستوران نمایش داده و اعمال می‌شه تا محصولات اصلی کافه و آبمیوه‌فروشی حذف نشن. حالت پیش‌فرض همچنان سریعه و تب اضافه باز نمی‌کنه؛ تطبیق صفحه‌ای قیمت تنها با انتخاب صریح خود کاربر انجام می‌شه. بعد از Reload خود افزونه و تب اسنپ‌فود، نسخه باید v0.2.1 باشه؛ یک جستجوی تازه بزن.


## اصلاح فهرست دسته‌بندی‌ها — ۰٫۲٫۱

پاسخ مسیر v4 برخلاف v1 شناسهٔ فروشگاه رو در `vendorCode` و وضعیت بازبودن رو در `isOpen` می‌فرسته. نسخهٔ ۰٫۲٫۰ فقط نام‌های قدیمی رو می‌خوند و فروشگاه‌های پاسخ جدید رو کنار می‌ذاشت؛ در نتیجه پیام «صفحهٔ خالی از رستوران» دیده می‌شد. حالا هر دو قالب شناخته می‌شن، امتیاز روی مقیاس درست میاد و نام بخش‌های بزرگ‌نویسی‌شده مثل `CAFFE` هم خوانده می‌شن.

ادامهٔ فهرست v4 از دو مقدار `count_details.vendor_index` و `item_index` استفاده می‌کنه؛ این‌ها بین صفحه‌ها و موقع ادامهٔ جستجو حفظ می‌شن. صفحهٔ صرفاً بنری پایان جستجو حساب نمی‌شه و یک کارت فروشگاه با شناسهٔ ناشناخته هم به‌اشتباه نادیده گرفته نمی‌شه. کنترل صفحه‌های تکراری و سقف درخواست‌ها همچنان فعاله.

بعد از به‌روزرسانی، خود افزونه رو Reload کن، تب اسنپ‌فود رو تازه کن و **جستجوی تازه** بزن. نسخهٔ بالای پنل باید **۰٫۲٫۱** باشه.


## دسته‌بندی محصولات در همهٔ جستجوها — ۰٫۳٫۰

بالای نتایج، فیلترهای «همه»، «غذای اصلی»، «نوشیدنی»، «سالاد»، «پیش‌غذا»، «دسر و شیرینی» و «سایر» با تعداد هرکدوم نمایش داده می‌شن. این دسته‌ها مربوط به خود محصولن و با بخش فروشگاه یا نوع رستوران فرق دارن؛ کافه‌رستوران هم می‌تونه توی چند دسته محصول داشته باشه. عنوان دستهٔ اصلی منو هم زیر عنوان محصول باقی می‌مونه.

دسته‌بندی اول از عنوان بخش عادی منو و فیلدهای `menuCategoryTitle`/`menuCategoryID` کمک می‌گیره. برای بخش‌های عمومی مثل پرطرفدارها و تخفیف‌دارها، دستهٔ اصلی همون سایز محصول از تکرارش توی منوی عادی بازیابی می‌شه؛ حتی اگر قیمت پایین‌تر مربوط به ردیف تخفیف‌دار باشه. اگر دسته مبهم باشه، نام محصول بررسی می‌شه. موارد نامشخص توی «سایر» می‌مونن؛ این یک نگاشت محلیه، نه تگ سراسری رسمی یا تشخیص صددرصدی.

فیلتر قبلیِ حذف نوشیدنی و مخلفات از رابط حذف شده. همهٔ محصولات مطابق قیمت، زمان، امتیاز و عبارت جستجو دریافت و نگه‌داری می‌شن؛ تعویض دسته فقط نمایش رو عوض می‌کنه و هیچ درخواست شبکه یا تب جدیدی ایجاد نمی‌کنه. تنظیم قدیمی `hideExtras` روی رابط تازه اثر نداره. پیش‌فرض نمایش برای رستوران، غذای اصلیه؛ برای سایر بخش‌ها و جستجوی دارای عبارت، همهٔ دسته‌هاست. «نمایش X از Y» تعداد همین دسته و کل موارد مطابق محدوده‌ها رو جدا نشون می‌ده. شمارنده‌ها مربوط به نتایج همین نوبتن، نه کل موجودی اسنپ‌فود.

بعد از Reload افزونه در chrome://extensions و رفرش تب اسنپ‌فود، بالای پنل باید **v0.3.0** ببینی. یک جستجوی تازه بزن تا محصولات دوباره با دسته‌های جدید خوانده بشن.
